# Lua: weapons

A weapon component's claim (`wa.weapons.replace`), its record tables, launching and firing, and its art. The rules every change follows are in
[contributing-with-an-agent.md](../../contributing-with-an-agent.md).

## Weapon claims

Lua sees `wa` and handles (`a`, `worm`). Not C++ names, not `unknownC`, not pointers.

A weapon is usually a **LuaActor**: its install calls `wa.weapons.replace` (no slot: it claims the one it was placed on), then `on_click` / `on_fire` spawn a body with a brain. An `on_click` event has `worm`, `x`, `y` (the click, from WA's fire context), `sky`, `weapon` (its id) and `vx`, `vy`: the shot's speed in that context, pixels/frame (0 when the click is eaten before WA fires, as with `eat_fire`); for a strike the sign of `vx` is the direction WA's arrow keys set, as Project X's airstrikes read it (0 or more: from the left). A click-only weapon's shot ends at the click as WA ends a weapon: the worm puts it away and the team takes its ammo and may select again (`click_finish = false` in the spec keeps WA's shot pending until the turn ends instead). Status tables (`gravity = true`, …) are the GUI path. Overlay a stock missile (`copy_from = "stock.<name>"`, its record fields in `missile = {...}`, `wa.on.gravity_*`) only when you still want stock flight.

- `worm_sprites_team_tint = { worm_sprites = { weaponlnk = "sprites/housing", ... }, colours = { six 0xRRGGBB, red to cyan } }` on a weapon claim: per pose, an overlay (the part to colour only) drawn over the claim's `worm_sprites` sheet, the same frame, multiplied by the drawing worm's team colour, on the GPU renderer. One sheet and one overlay stand for six team-coloured copies, without six copies' atlas space. Without the shader renderer the sheet draws uncoloured.
- `available_in_caves = false` on `wa.weapons.replace` disables that custom weapon on cavern maps and excludes it from crate drops there. With stockpiling, its ammo is kept for a later open-map round and remains blocked in caves; otherwise it starts caves with no ammo. `true` explicitly allows caves; omitted, it inherits the `copy_from` or `.wep` source record's rule. The firing record stays intact, so a scripted strike can use a bullet record while declaring its own cave restriction. Highlander's “Dealt on cavern maps” remains a separate pool-dealing option.
- `wa.world.keys().ctrl` is synchronized Ctrl. `stock_fire_choice = { held = "ctrl", alternate = "stock.surrender" }` on a weapon claim uses its normal stock fire unless Ctrl is held, then fires a pristine stock Surrender record through the existing dispatch. On the Skip Go slot, Ctrl also shows the stock Surrender armed and fire sprites while held. The choice affects only that claim.
- `wa.world.keys().plus_key` is the + key (top row or keypad), synchronized with the other keys: every peer reads the turn player's.
- `wa.world.keys().minus_key` (the - key, top row or keypad), `.alt` (Alt) and `.pause_key` (Pause/Break) are synchronized the same way. Highlander's Portal Gun: - and + pick the portal, Pause switches the team's pair on and off.
- `worm_sprites_toggle = { key = "plus_key", worm_sprites = { ... } }` on a weapon claim: sheets drawn instead of its `worm_sprites` while the worm's toggle is on. The engine flips a worm's toggle on each press of the synchronized + key while it is the turn's worm with that slot selected, so a pack keeping its own mode by the same rule stays in step. A one-shot pose plays again from its start in the new sheet. Highlander's Electromagnet: blue repelling, red attracting.
- `api_version = 4`: every weapon by id, never by slot, and a weapon's record as named tables (`missile`, `clusters`, ...). Renaming the Lua API is a breaking change: bump it.
  Waiting for the next `api_version`, which drops them: `wa.world.keys().sprint` (now `shift`), `worm:set_state("sinking")` (now `tumbling`), `worm:set_state` itself (a debugging tool), and an actor hit's `blast_damage` (now `power`). Add an old name here when it is kept beside a new one.

## Claim fields and records

`a:frame(i)` holds a LuaActor on one frame of its current sheet (zeroes the loop delta). `worm.facing` is read-only (−1 left, +1 right). `cluster = { sprite = "sprites/bits", homing_sprite = "sprites/bits_homing" }` takes pack sheets for the cluster bits and for what homing bits draw while they home (their render timer). `fire_repeat = 5` runs stock FireWeapon that many times per shot, in the same frame (PX’s Real Shotgun: five pellets). `plane = "sprites/plane"` on a strike slot gives the strike its own plane (the strike’s `+0x38`, where the stock jets are 86 and 87). `sheep_sprites = { "sprites/a", "sprites/b" }` on a roaming animal (built on `stock.super_sheep` or `stock.aqua_sheep`) gives it its own two flying sheets, written to its record's `sheep.flight_1` and `sheep.flight_2` (`+0xE0`/`+0xE4`, the two sheets WA alternates while the sheep is steered; WA's are spsheep1/2 and aquashp1/2), installed as WA sprites like a plane; prefer it to `sprite_overrides` on WA's sheep sprites, which would change every Super or Aqua Sheep in the match. `sprite_overrides = { wsvbd = "sprites/trail", [466] = "sprites/x" }` on `replace` swaps any stock sprite (Gfx.dir name or id 1–799) for a pack sheet for the whole match, as PX’s `SetSpriteOverride` does: every user of that sprite draws it, so only override sprites nothing else in the match needs (PX repurposes the Salvation Army’s `wsv*` frames as trails). `worm_sprites` on `replace` remaps that weapon’s worm poses only (`weaponlnk` / `wthrow` and slope variants; on the uzi, minigun, shotgun and handgun also `weaponfire*`, the gun firing, which falls back to the `weaponlnk*` sheet; on a weapon that is WA's Longbow, its own sheets `wbowlnk*` `wbowbk2*` `wbow*` `wbowp*` `wbowf*`, drawn at WA's phase, so a recolour of the same frames: the Ice Arrow). `ev.damage` on an actor brain is stock blast falloff this tick. `wa.actors.spawn{ as_object = true }` puts the actor in WA's oil-drum collision layer (17) instead of the missiles' (15), as Project X's `SetLayerOverride(LAYER_OILDRUM)`: WA's fires then hit it (a fire hits only layers 2..5 and 17), and its guns, missiles and worms treat it as an object. `wa.actors.spawn{ mask = true }` stamps the actor's opaque outline into WA's walk grid; `mask_worms`, `mask_weapons`, `mask_land`, `mask_actors` and `mask_rope` (each defaults to `mask`) say what it holds against: `mask_rope = false` lets WA's ninja rope pass it, as the rope passes oil drums, while worms still stand on it and shots still hit it (the Sentry Gun and Laser; engine `rope_passage`). `wa.actors.spawn{ shape = "missile" }` gives the actor WA's missile collision shape (the one WA's missile constructor takes for the Sheep's and Skunk's records) instead of the worm shape it borrows, and `a:fits(x, y)` (a read, pixels) is WA's own test of the actor's shape at (x, y) against the land: true when it touches none, as `worm:fits` is for a worm. `on = { frame = fn, land = fn, hit = fn }`: with `hit`, WA's blasts (0x1C) and hits (0x4B, Project X's `M_GUNEXP`) on the actor go to `hit(a, hit)` instead of to the actor's speed: `hit.kind` is `"blast"` or `"hit"`, `hit.hit_kind` WA's kind of hit (1 is a fire's), `hit.x`/`hit.y` where it came from, `hit.vx`/`hit.vy` the push WA would have given the actor (pixels/frame; a blast's is WA's own falloff), `hit.damage`, `hit.team` (-1 for a blast). Blasts additionally provide `hit.power` (older name `hit.blast_damage`), their damage before native distance falloff, as a worm's `wa.on.hurt` names it; `hit.damage` remains the native distance-adjusted amount. The extra field is nil on ordinary hits. Callback delivery still follows native hit reception. For an actor the pack moves itself, which would lose a push WA wrote into its speed. Overlaying a mine’s fire (`copy_from = "stock.mine"` plus `on_fire`) keeps placement/retreat and routes the body through the existing projectile wrap. `wep = "x.wep"` on `replace` gives the slot a Project X weapon file’s firing (a PX `.wep` is WA’s weapon table entry behind a 4-byte tag), exclusive with `copy_from`; its name is the default name, the record tables and pack art still win, and a sprite field naming a PX-only sprite keeps the slot’s own (see `mods/px/weapons/chilli_bomb.lua`). The weapon's record is written as named tables on `replace`, over the base `copy_from` / `wep` laid down (`weapons::record`, one field table, exported as `web/weapon-editor/record_fields.json`):
  - `fires = { type, method, subtype, creates_projectile, launch_power_pct }`;
  - `handling = { remember_selection, shots, ends_turn, retreat }`;
  - `missile = { collides, explosion = { power, push_pct, bias, variation }, sprite, animation, trail = { sprite, power, speed }, speed_pct, wind_pct, random_motion, gravity_pct, countdown, fuse, flight_sound, explosion_sound = { enabled, sound, before }, explode_on_space, action, bounce = { bounciness, terrain_keep_speed_pct, sound, max_bounces }, homing = { kind, arm, time, sprite, animation, trail }, burst }`;
  - `clusters = { count, angle, spread, bit = { ... } }`: `bit` is the missile body again, for the cluster bits, with `sprite_count`;
  - `mine = { proximity, arm, detects, fuse, explosion = { bias, push_pct, power } }`, `gun = { bullets, damage, shot_interval_ms }`, `strike = { plane, count, spacing, munition }`;
  - `fire_punch = { knockback }`: native Fire Punch hit strength in pixels/frame, in steps of 0.1, before WA's hit modifiers; `knockback = 8` is the native record's `80`. This changes the victim's knockback, not the attacker's jump. Only Fire Punch behaviour (`fires.type = 4`, `fires.subtype = 1`) accepts it, including weapons copied from stock Fire Punch or a `.wep`. Other melee actions have different layouts.
  - `raw = { [0x80] = 7 }`: any patchable dword by its entry offset, for what has no name yet.

  `fires.launch_power_pct = 50` gives a missile-family weapon preset launch power in percent; values above 100 are allowed. `"charged"` (or numeric `0`) selects WA's charging behaviour for launched/thrown weapons. Placed missiles also accept numeric launch power, but this does not make placement chargeable. `gun.shot_interval_ms = 63` sets a gun's interval between shots in milliseconds. These are different family-specific uses of the same record location; guns refuse launch power and missiles refuse gun timing. Neither changes an explicit `vx`/`vy` passed to `wa.weapons.launch`. Reading launch power with `wa.weapons.data` returns `"charged"` for zero.

  See [Weapon records](../../docs/weapon-records.md) for the modder-facing reference,
  including inheritance, field meanings, units and per-shot overrides.

  Additional named fields:

  | Table | Fields and units |
  |---|---|
  | `gun` | `spread_deg`, `burst_size`, `burst_spread_deg`, `hit_flags`, `explosion = { bias, push_pct, variation }`, `impact_effect`; `damage` remains the damage field. Spread is the full angular width, centred on the aim. |
  | `fire_punch` | `damage`, `knockback` (pixels/frame); special subtype 1 only. |
  | `drill` | `duration_ms`; native Pneumatic Drill behaviour, special subtype 8 only. |
  | `parachute` | `wind_pct`: wind response percentage (`100` normal, `0` ignores wind); native Parachute behaviour, special subtype 12 only. Steering and initial momentum remain unchanged. |
  | `missile` | `collision_shape` (native numeric physical-outline preset, independent of sprite size), `alarm_worms` (boolean, enables a nearby worm's pre-explosion alarm cry). These header settings have no independent `clusters.bit` equivalents. |
  | `missile.bounce` | `flags`, `contact_sides` (native side mask for the bounce limit and contact explosions), `extra_reverse_chance_pct` (additional horizontal reversal and vertical-speed-based kick before normal collision processing), `explosion = { bias, push_pct, power, variation }`, alongside the existing bounce settings. |
  | `missile.roam` | `movement_flags`, `explode_flags`, `walk_speed` (pixels/frame, steps of 0.02), `edge_jump = { angle_deg, speed, sound }`, `jump = { angle_deg, speed, sound }`, `terrain_offset` (signed pixels used when drawing the grounded animal). Jump speed is the nominal pixels/frame in steps of 0.06; WA applies its native random variation of roughly ±1/6. Negative native jump-angle sentinels retain their explosion behaviour. |
  | `missile.roam.gas` | `start_delay_ms` (nonzero starts the emission countdown; zero leaves it unarmed), `poison_power` (native poison message amount), `animal_sprite` (the animal's pose while emitting, a stock sprite name or ID). |
  | `missile.dig` | `sound`, `dive_sprite`, `sprite_1`, `sprite_2`, `sprite_3` (stock sprite names or IDs). |
  | `clusters` | `launch_power_pct`, `power_variation_pct` for cluster payloads (native selectors 1 and 3). The first is launch strength relative to WA's base 24 pixels/frame; the second randomly reduces that strength by up to the given percentage. Fire payloads reuse these offsets for other meanings and do not expose these fields. |
  | `missile.fire` | `spread_delay_ms`: delay before the next fire-spreading generation, checked in 20 ms steps; requires `missile.burst = "fire"` when the payload is explicitly set. |
  | `missile.fire` | `burn_time_ms`: nominal settled burn time of ordinary fire; falling pauses natural decay and native randomness can shorten it. Persistent native fire modes consume this reserve on hits instead. Zero does not mean unlimited. Fire payload only. |
  | `missile.fire` | `spread_generations`: nonnegative whole successor depth, `0` initial flames only. `decay_mode`: `"resting"` spends reserve while settled; `"on_hit"` spends it on hits. Fire payload only. Legacy `clusters.count`/`clusters.angle` writes remain compatible; readers use the fire names. |
  | `strike` | `munition_speed`: initial horizontal speed of dropped munitions along the plane's direction, in pixels/frame, steps of 0.01. The aircraft's movement is separate. `plane_sound`: native aircraft sound ID, zero off. |

  `clusters.bit` mirrors the applicable missile action settings, including `bounce`, `roam` and `dig`. Strike munitions use the same `missile` and `clusters` names with their native layout shift handled by the engine. Action and payload mismatches are refused when explicitly set in the same spec. `wa.weapons.data` exposes only the groups appropriate to the record's current action and payload. Pixel-unit settings return pixel values; native flags retain their integer bitmasks. `jet_pack.fuel` is restricted to special subtype 23, so other special actions no longer expose their parameter as fuel.

  `explosion.power` is the damage and radius together (the scheme's power), `push_pct` only the knockback; `bounce.bounciness` is extra bounce on top of a grenade's (0 WA's Grenade, 60 the Banana Bomb's); `bounce.terrain_keep_speed_pct` is the % of its speed a missile keeps on hitting terrain. A group the weapon's family (its fire type and method, after `fires`) doesn't have is refused ("missile.speed_pct is not in a gun weapon's record"), and so is `bounce` on a homing body or `homing` on a bouncing one, by the record's `action`. A strike's munition is a missile 0x14 bytes on; the engine shifts it. Names come from the Record Lab (`labs.rec_*`, a retired example); a field nobody has settled stays `raw`. Enum fields take names (`action = "bounce"`, `burst = "clusters"`, `homing.kind = "lock"`, `strike.munition = "missiles"`) or numbers. PX sprite ids keep the slot's stock art as with `wep`. `wa.weapons.data(id)` reads a weapon's record back as the same tables, with `fires.as` naming its family: a placed weapon's as this round has it, WA's untouched one for a `stock.<name>` not on the panel.
`mole_dig_rotation = { moledive = "sprites/dive.png", moledig1 = ..., moledig2 = ..., moledig3 = ... }` replaces the mole strike's digging frames globally for the match, as PX's `SetSpriteOverride` does; any subset of the keys works, and no other sprite is accepted. A fifth key, `mole`, is WA's underwater variant of the dive frame (a diving mole that enters water switches 158 → 663; the dig frames have none). If a pack overrides `moledive` but not `mole`, the dive sheet sinks under PX's sinking tint, `RGB(90, 90, 240)` multiplied in, instead of turning back into WA's mole. The PNG/GIF must live in the bundle; the first loaded claim for a frame wins, and every mole in the match uses it.

## Weapon steps, launching and firing

- Weapon steps (do not steal MineEntity): `on_place` / `on_proximity` / `on_explode` as a function or `{ spawn = { sprite = false, explode = { damage = 0, id = 40, now = true }, damage_worms = false } }`. Same `spawn` table as `on_fire` / `on_click`. `sprite = false` is invisible (blit id 1023). `explode.now` blasts at spawn. Nested `on_explode` on a spawned actor fires when that actor blasts. Stock `CreateClusters` is not this path yet.
- `wa.weapons.launch{ weapon = "px.double_bazooka", owner = worm, x, y, vx = 0, vy = 0, missile = { explosion = { power = 40 }, fuse = 5000 } }` fires a real WA missile from a weapon's fire params, as WA's `CreateWeaponProjectile` does and Project X's `new CMissile(...)`: a placed weapon fires as itself (its own claim), as does one a selected component `launches` that the profile doesn't place (below), `stock.<name>` as WA's own on its own slot. WA flies, draws, trails and explodes it as its own, and it is that weapon's missile to every hook (`m.weapon`, `on_explode`). `owner` is the worm it is fired for (its team and worm number); positions are pixels and speeds pixels/frame. `missile = {...}` and `clusters = {...}` (the record tables' fields: `missile.fuse`, `missile.flight_sound` (0 for none), `missile.burst`, `missile.countdown`, `missile.explode_on_space`, `missile.bounce.terrain_keep_speed_pct`, ...) change this missile only, in a copy of the fire params. Simulation callbacks only. It returns the missile's id, the `m.id` of `wa.on.missile_frame`; a missile's `on_explode` event carries its id as `ev.missile`. The weapon's record must be one WA builds a missile from: launched or thrown (fire type 1, method 3) or placed through WA's projectile path (fire type 2, method 2); any other (a cursor, gun, mine or special record) builds no missile, where WA's missile constructor would crash on its fire params: `launch` returns `nil` and logs why, once a match per weapon, so a brain that checks `if id then` goes on. Other failures (WA's object pool full) still raise an error; a brain that must never stop wraps them in `pcall`, since a brain that errors every frame never finishes, and a turn waiting on its actor never ends. A weapon with such a record launches its rounds from one that is (e.g. `stock.bazooka`, with `missile = {...}` for the shot).
- `wa.weapons.click{ weapon = "px.bowling_ball_strike", worm, x, y, vx = 0, vy = 0 }` runs the `on_click` function of that placed weapon, with the event a click there gives it (`ev.x`, `ev.y`, `ev.sky`, `ev.weapon`, `ev.worm`, and `ev.vx`/`ev.vy` as the shot's speed: for a strike, the sign of `vx` is its direction). Only the weapon's handler runs, as its component: WA's own fire does not (no wind-up, no ammo used, the turn goes on). For firing another component's click weapon from a script (a stress test, a scripted event, a computer player). It errors when that weapon isn't placed or has no `on_click` function (an `on_click = { spawn = ... }` claim is the engine's own). Simulation callbacks only.
- `wa.weapons.fire{ weapon = "px.electromagnet", worm, x, y, vx = 0, vy = 0, ... }` runs the `on_fire` function of that placed weapon, with the event a shot there gives it (`fire.x`, `fire.y`, `fire.vx`, `fire.vy`, `fire.weapon`, `fire.worm`), as its component, as `wa.weapons.click` does for `on_click`. The spec's other fields go into the event too, for a handler that reads them (Highlander's Electromagnet: `polarity`). Only the weapon's handler runs: WA's own fire does not. Simulation callbacks only; an error when that weapon isn't placed or has no `on_fire`.
- `on_fire` on a gun slot (fire type 1, method 2: uzi, minigun, handgun, shotgun) takes every shot WA fires, and WA's bullet is skipped, as Project X's `FireFinal` without `super`; `fire.x`/`fire.y` are WA's prepared shot position, and `vx`/`vy` its native unit firing vector, including any spread already applied by WA. Multiply that vector by the desired projectile speed; do not add another aim/spread calculation. A missing native shot descriptor falls back to the worm's position and zero velocity. On a projectile slot it replaces the projectile, as before. On a special record (fire type 4: the utilities, Jet Pack, Skip Go, ...) it replaces WA's special fire, which WA picks by the record's subtype, the turn utilities' switching their bit on for the team: the shot around it goes on as WA's, and the worm holds WA's pose for that subtype (the utilities' `wutllnk`), so a custom utility built on one (`copy_from = "stock.double_turn_time"`) runs only its Lua.
`wa.weapons.fire_bullet{weapon, owner, x, y, dx, dy, damage?, push_pct?, ignore?}` fires
one native hitscan round from a pixel position. `weapon` is `stock.shotgun`,
`stock.handgun`, `stock.uzi` or `stock.minigun` (WA's own, a template); `owner`
must be a living worm. Direction is normalized;
nonfinite or zero directions are rejected. Optional `damage` (0..1000) changes
only hit damage. Optional `push_pct` is a whole percentage from 0 to 1000 of
the selected stock gun's normal knockback: omit it or use 100 for normal push,
0 for none, 250 for 2.5 times normal. Both overrides affect only this round;
impact graphics remain stock. Stock settings are
captured before any weapon's claim. There is no weapon selection, firing pose,
ammo consumption or turn-ending action, and no automatic spread/burst. Lua
controls those. `ignore = {body, ...}` excludes those live bodies and their
actor-added mask pixels only during tracing; terrain and overlapping other
masks stay solid, and full collision is restored before damage/effect callbacks.
Rounds also hit worms in native airborne/control layers (jump, Jet Pack,
rope and Bungee), allowing WA's hit response to interrupt their movement.
Simulation callbacks only; returns no projectile handle because hits are immediate.
A weapon may declare a separate `projectile` record for `wa.weapons.launch`.
See [Separate projectile records](../../docs/weapon-records.md#separate-projectile-records)
for the declaration and its relationship to native gun timing.

## Panel, visuals, held art and grants

Completed acquisitions are `wa.on.weapon_grant(fn)` events: {% raw %}`{worm_id, items = {{weapon, amount}, ...}, x, y, alliance, frame, source}`{% endraw %}. Positions are captured pixel coordinates; `alliance` is the active coalition's colour at grant time. Crate awards and positive virtual inventory changes report automatically after the stock simulation step; a transfer reports one batch with virtual copy counts. Optional transfer `x` and `y` (pixels) override the acquisition position; otherwise it is the recipient's position. Initial `deal`, `apply`, direct ammo refills/refunds and removals stay silent. Scripts doing direct ammo grants can call `wa.weapons.notify_grant{worm, items, x?, y?}` afterwards, from simulation callbacks; it never changes ammo.

`wa.weapons.visual(weapon)` (a placed weapon's id) returns a static panel symbol `{sprite, frame, width, height, kind = "icon"}`, or nil when unavailable. Black and near-black pixels in the popup copy are transparent (all RGB channels at most 24/255). These previews copy into the GPU atlas without extra WA sprite slots and work across bundles. `wa.world.frame()` is the match's simulation frame (50 per second). `wa.world.is_local_alliance(colour)` is allowed only in draw/HUD callbacks: online coalition membership includes local allied teams and excludes spectators; offline it follows the coalition currently using the shared screen. Capture ownership during acquisition; filter locally only while drawing. See the collect viewer in `mods/examples/utilities` (`features/collect_viewer.lua`).

`panel_icon = "sprites/icon.png"` on `replace` puts a pack PNG in the stock weapon panel: 32×32 (WA's and every PX icon's full size; the panel shows the centre 24×24) or up to 24×24, quantized to WA's icon colours with an automatic greyed frame. `panel_icon = "banana"` still borrows a stock icon. See `docs/weapon-panel.md`. `panel_icons = { "b.png", ... }` beside a PNG `panel_icon` gives the weapon more icons, made the same way when the match loads; `wa.weapons.panel_icon(weapon, n)` shows icon `n` in that weapon's tile (0 is `panel_icon`, 1.. the `panel_icons`). Only the panel changes, so any callback may call it and each machine may show its own (the Electromagnet shows the turn worm's mode from its HUD hook); showing the icon already shown does nothing.

`hold = { sheet = "sprites/weapon", hand = "sprites/hand", weap_radius = 9 }` on `replace` draws a GPU sheet over the worm's aim pose. The engine follows WA's live aim and facing, grows the hold in over 20 game frames, hides it immediately on walking (state 0x66) by default, and restores it when aiming resumes. `hand` is optional. Placement fields are `weap_radius`, `weap_rotation`, `weap_radial_rotation`, `hand_radius`, `hand_rotation`, `hand_radial_rotation`, and `hand_scale` (PX `CWormAnimParams`, with defaults of 1). `static = { weap = -0.1, hand = 0.4 }` fixes angles in multiples of π. `sheets = { "sprites/weapon_open" }` lists other sheets the held art may switch to, with the same frames and placement; `wa.weapons.hold_sheet(weapon, n)` draws sheet `n` (0 `sheet`, 1.. `sheets`) for that placed weapon, as Project X swaps its WormSprite's sprite (the Gravity Gun's claws opening): only the draw, from any callback, `engine/worm_hold.rs`. `frames` and `anim_speed` animate the weapon sheet. `keep_while_firing = true` retains it in WA's firing poses; `put_away = true` keeps the held art visible while it swings down and shrinks away over 20 game frames after firing, including while walking; it defaults to false. `thrown = true` skips the put-away animation. `flash = { sheet = "sprites/flash", out = 30, side = 2, scale = 0.45, frames = 3 }` draws a short additive muzzle flash after a shot. These sheets use the GPU atlas and do not consume WA sprite slots.

## Sprites, trails and animation

Sprites: pack PNG strip (`sprite_columns`), GIF, frame folder, or a Gfx.dir stem (`missile`, `grenade`, `uzihit`, …) plus aliases `bazooka`/`holy`/`mine`/`cursor`. Map palette applies. Sounds: pack WAV on the overlay, or a stock index.

For a weapon's own native trail, set
`missile = { trail = { sprite = "sprites/my_trail.png" } }` in its replacement
declaration. The engine loads and scopes that image to the weapon; it does
not override a stock sprite globally. The path is an installation declaration,
not an image to load from a simulation-time `wa.weapons.launch` call.

Declare a sheet's animation in the bundle's `mod.toml`, keyed by the same
pack-relative path Lua uses:

```toml
[sprites."sprites/balloon/balloon.png"]
fps = 15
play = "pingpong"

[sprites."sprites/wide_frames.png"]
frames = 12
fps = 15
play = "loop"
```

All three fields are optional. `frames` explicitly slices a vertical PNG
into that many equal-height cells, including non-square frames; without it,
vertical strips use square cells and `sprite_columns` still selects horizontal
strips. `fps` is 1..50. `play` is `"loop"`, `"once"` or `"pingpong"`.
Undeclared folders still loop at 15 fps, PNGs play once at 10 fps, and GIFs
keep their timing and looping. Overrides also apply to `wa.assets.load`,
held/worm art, masks and extra/cluster sheets. Native worm pose replacements
keep WA's clamped phase handling; the declaration still controls their
slicing, speed and any expanded ping-pong sequence. PNG strips save file opens
compared with frame folders.

Ping-pong expands at load time to `0, 1, …, n-1, n-2, …, 1`, then loops.
Every consumer sees the expanded count (`2*n-2`, or `n` for one/two frames),
including explicit `a:frame(i)` selection and collision masks. Lua that sets
frames itself must use that expanded sequence; it controls its own timing
instead of `fps`. No additional SPR playback flag is used.
